# @minderal/app

A minimal Vue app that exercises `@minderal/core` directly — no state management, no
component library, one component.

```
npm install
npm run dev          # http://localhost:5173
```

Needs CouchDB for the remote path:

```
cd ../core && npm run couchdb:up
```

Leave the URL blank to use a local IndexedDB database instead of a remote server.

## Resuming a session

On load the app connects **with no credentials** before showing the login form. The session
cookie is HttpOnly and cannot be read, but CouchDB answers `GET /_session` as the real user
whenever one is live — so a credential-less connect is both the check and the connection,
and `connection.user` says which happened: a name means signed in, `anonymous` means the
form is needed. The login controls stay hidden until that probe settles, so they do not
flash for a returning user.

## Testing from a phone

`npm run dev` listens on every interface, so the dev server is at
`http://<your-lan-ip>:5173`. CouchDB is already published on `0.0.0.0:5984` by
`compose.yaml`, so it is reachable on the same address with no change.

The CouchDB URL defaults to the **hostname the page was served from**, not `localhost` —
on a phone `localhost` is the phone. That also keeps the two on the same site: same host,
different port, which is what lets the `AuthSession` cookie through. No HTTPS is needed
for this, and adding it would break the cookie unless CouchDB were served over TLS too,
because Chrome treats `https://host` and `http://host` as different sites.

Both machines have to be on the same network, and a firewall that blocks inbound 5173/5984
will stop it.

## Navigating

The table shows the children of whatever neuron is open, via `listByParentId`. Clicking a
row's id opens it; the breadcrumb walks back up. The open id lives in the URL as `?id=`, so
links are shareable and browser back/forward work through `popstate`.

An `?id=` that names nothing in the open database — deleted since the link was made, or
belonging to a database you have switched away from — is not treated as an error. The page
drops to the root level and drops the parameter, replacing the history entry so Back does
not lead straight back to the dead id. `buildTrail` returns `null` for that case, which is
distinct from the empty trail that means "already at the root".

At the top level the table lists `listByParentId(null)` — the roots — rather than every
document, so navigation is a tree at every level. The graph draws the top level as a 🧠 node
reading "start creating from here"; it is synthetic, with no neuron behind it, so it cannot
be renamed or deleted. The same 🧠 stands for the top level everywhere it is referred to —
the breadcrumb, the table's parent column, and the details panel's parent link. `Database.list()` is therefore not used
by this app.

Creating while a neuron is open sets the new neuron's `parentId` to it.

## Neuron identity

Ids are `neuron:<uuid>`, generated by core with the `uuid` package rather than
`crypto.randomUUID`, which is undefined outside a secure context — including a dev server
reached over plain HTTP on a LAN address, which is how you would test from a phone.

What you type when creating a neuron is its **name**. `value` is separate content, optional
at creation, and a node shows it as a second line only when it is there.

## Renaming

Clicking a neuron's name opens an editor in place — on the node in graph view, in the name
cell in the table. Enter calls `Database.rename`, which stamps `updated_at` and writes
through `Database.update`; the new name arrives back through the change feed like any other
change, so nothing refetches explicitly. Escape abandons the edit, and blurring closes an
untouched editor but leaves an edit in progress alone, matching the draft's rule.

Only the name text opens the editor, so the rest of the node still navigates.

## Ordering

Children come back newest first, by `created_at`, with the id as a tie-break for neurons
written in the same millisecond. Core sorts in memory rather than through a Mango sort:
`findAll` already pages the whole result in, and an indexed sort would need the sort field
in the index and matching directions on both engines.

## Deleting

Deletes are soft and recursive: `Database.delete` stamps `deleted_at` on the neuron and its
whole subtree in one bulk write, and the documents stay in CouchDB, hidden from `get`,
`list` and `listByParentId` unless `{ includeDeleted: true }` is passed. A descendant that
was already deleted keeps its original timestamp. Both confirmations say "and everything
inside" when the neuron has children.
The table has a trash icon per row and the graph an ✕ on each node; both ask inline rather
than through a modal dialog, so nothing blocks the page. The graph's confirmation replaces
the node's own body — beside the node is where children are drawn, and they paint over it. Deleting the neuron you are
currently inside steps up to its parent.

## Live updates

Nothing refetches because of a write. `Database.watch` drives every refresh: the app
subscribes once per open database and refetches, debounced, when a change touches the level
on screen — matching on `parentId`, `previousParentId`, the open neuron, or an ancestor. The
debounce lives here rather than in core, which should not hide changes from a listener that
wants them all.

The header carries a **live** badge. If the feed drops the badge turns red and says why;
core probes the server before reopening, and on recovery the badge clears and a refresh runs
to catch up on whatever the feed missed while it was blind.

Replication is not wired into the app yet — `local.syncWith(remote)` exists in core and is
covered by tests, but the app still opens a single connection.

## What a reload starts from

The server URL and the database name are remembered in `localStorage`
(`minderal.last-url`, `minderal.last-database`), written only once a connection
has answered and a database has actually been read. A reload resumes the session
against the remembered URL; with nothing remembered there is no probe at all, so
the login form paints immediately instead of waiting out a fetch timeout against
a guessed host. The URL field still prefills with `protocol//hostname:5984` as a
suggestion — a default is fine to type into a field, not to connect to.

The database picker is a `<select>` listing every database on the server, plus
`+ new database…`, which swaps in a text field. An `<input list>` narrowed its own
suggestions against whatever was typed, so the name already in the field hid all
the others. Opening a database is what creates it, so naming one is all it takes.

## Attributes

The **open** neuron shows its attributes inside its node, followed by a dashed
`+ Add attribute` placeholder; clicking it swaps in a name and a value input, Enter writes,
Escape abandons. Hovering a row reveals an × that removes it.

Only the focused node does this, and it grows to fit. `d3-hierarchy` lays siblings out on a
fixed `nodeSize`, so a variable-height node would overlap its neighbours — but the open
neuron is alone in its column, so nothing has to move. The viewBox measures each node by
its own height rather than assuming a uniform one.

Nothing refetches on write here either: `setAttribute` updates the owner document, and that
change arrives through the feed like any other.

## Views

A Table / Graph toggle switches between the list and a node diagram — the open neuron, its
parent, and its children. Every node but the open one is clickable, so the graph navigates
both up and down. The mode rides along in the URL as `&view=graph`, so a link
carries both where you are and how you are looking at it.

The graph uses **`d3-hierarchy`** for layout only: it computes node positions, and Vue
renders the SVG in its own template. Nodes are therefore ordinary elements with normal
click handlers and the same theme tokens as everything else — no second rendering system
to reconcile with Vue. When relation documents arrive and the tree becomes a real graph,
`d3-force` slots into the same place under the same split.

Creation in graph mode happens on the node, so the bar carries no create form there.
Every node has a `+` handle: clicking it adds a dashed node in the **first child position**
with a text field in it. Enter creates the child, Escape cancels. Clicking the node body
still navigates. Adding to a node other than the open one also opens it, so the new child is
visible rather than created off-screen.

The draft is laid out by d3 as a real child rather than floated beside the node, which is
what stops it landing on top of the existing children. It comes from state a refetch never
touches, so an incoming change redraws the tree around it without disturbing what is being
typed, and it is dismissed the moment the write succeeds because the refetch is on its way.
Blurring an empty draft discards it; one with text typed into it stays, because losing what
someone wrote is worse than a stray node.

The SVG carries explicit `width`/`height` in pixels matching its `viewBox` 1:1. Letting it
stretch to the container instead scales the whole drawing, label text included.

## Browser notes

Core targets Node and the browser, and three things have to be bridged in `vite.config.ts`
and `index.html` for PouchDB to run in a bundler:

- `pouchdb` is aliased to `pouchdb-browser`. The default entry is the Node build, whose CJS
  interop breaks under Vite (`Class extends value [object Object]`).
- `events` is aliased to the npm shim. PouchDB does `class X extends require('events').EventEmitter`,
  which resolves to a Node builtin stub without it.
- `window.process` and `window.global` are defined in `index.html`, before any module loads;
  `pouchdb-all-dbs` uses `process.nextTick`.

CouchDB needs CORS for the browser to reach it — see `../core/couchdb/local.ini`, mounted by
`../core/compose.yaml`. It sets `origins = *` with `credentials = true`; CouchDB then echoes
the request's Origin instead of a literal `*`, which is what credentialed CORS requires and
what lets the `AuthSession` cookie flow. So the dev server's port doesn't matter — handy,
because Vite silently moves to 5174 if 5173 is taken. **Development only**: `*` lets any
page on any origin make credentialed requests to your CouchDB.
